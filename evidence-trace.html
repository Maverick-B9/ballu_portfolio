01THE PROBLEM

Investigative evidence needs organised handling, traceability and clear technical context.

If you cannot show that a file has not changed, and who touched it and when, the evidence loses its value. The platform is built around answering those two questions at every step.

02THE APPROACH

A 6-module web platform covering acquisition, hashing, entropy analysis and reporting, on a MySQL backend with Flask.

MD5, SHA-256 and SHA-512 hashes provide tamper detection: if a file changes, its hash no longer matches. Role-based access control limits what each user can do, and audit logging records actions. Investigator-ready dashboards pull it together.

03HOW IT
WORKS

A simplified view of the flow, step by step.

  1. Acquire

    Evidence is brought into the platform as a record.

  2. Hash

    MD5, SHA-256 and SHA-512 fingerprints are stored for tamper detection.

  3. Analyse

    Entropy analysis adds technical context about the content.

  4. Report

    Findings are presented on investigator-ready dashboards and reports.

ACROSS EVERY STEPRole-based access control decides who can do what.
ALSO ACROSS EVERY STEPAudit logging records actions for traceability.
